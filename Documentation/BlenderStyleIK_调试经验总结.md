## 一、问题与根因

### 1.1 现象

节点每帧求值，末端（effector）**永远精确到位**，链的整体朝向也稳定地指向 pole target，
但**每根骨骼的径向角（roll）逐帧跳变**——末端目标移动不到 0.01 单位，径向角可以翻 90°。

### 1.2 三个症状，一个病根

排查中最关键的认知是：三个看似独立的问题其实是**同一条根因**。

| 症状 | 表面解释（都验证为错） | 真实原因 |
|---|---|---|
| pole 完全不起作用 | 公式抄错了 / 参数没接进代码 | `dir == poledir` → 约束矩阵恒为单位矩阵 |
| 末端每帧都精确到位 | 求解器收敛能力强 | 求解起点本身就已经压在目标上 |
| 径向角逐帧跳变 | 雅可比列形式错 / 阻尼系数不对 | 求解起点逐帧不同 → 落在不同解分支 |

根因：本节点的**输入姿态与 IK 输出是同一批骨骼的同一份数据**。节点每次求值都把自己上一趟的结果
写回 `Current`，于是同一帧内第二趟求值读到的起点就是第一趟的输出——起点变成了"上一次的解"。

```
起点 = 上一次的解
  → 起点逐帧不同
  → 位置迭代在近奇异构型下有多个解分支，分支选择对起点极其敏感
  → 每根骨骼的径向角逐帧跳变
  → 同时：起点末端恰好压在目标上 → dir == poledir → pole 约束恒为单位矩阵
```

### 1.3 修复

**求解起点改为"重建出的、未被本节点写入过的姿态"**：

- 用骨骼的 `InitialLocal`（本节点只写 `Current`，从不写 `Initial`）逐级级联；
- 链根骨骼接在**父级的实时姿态**上（父级是 FK 骨骼，不属于本链，不受本节点影响）。

得到的链在数学上就是"如果这条链上没有 IK，它此刻会是什么姿态"，且在一帧内恒定。
径向角漂移随之消失。

pole 则改为**求解后的显式对齐**（见 2.2）。

### 1.4 泛化结论

> 当一个迭代式求解器"结果基本正确、但某些局部量乱跳"时，第一个该问的不是"梯度/阻尼对不对"，
> 而是**"起点是不是确定量"**。解的唯一性来自起点的确定性；起点被自己的写回污染，任何数值精度都救不回来。

## 二、数值与数学上的教训

1. **不要在没有验证的前提下继续搭楼。**
   整个问题卡最久的一环是"我们施加角度增量的方式，与雅可比矩阵列的形式是否一致"。
   用有限差分把三种候选列形式逐骨骼逐轴对了一遍：

   | 雅可比列写法 | 与有限差分的一致性 |
   |---|---|
   | 世界列 `P × (Rot·e_j)` | 吻合到 1e-10 ✅ |
   | `Rot⁻¹(P × (Rot·e))` | 不吻合 ❌ |
   | `(Rot⁻¹P) × e` | 不吻合 ❌ |

   一次就封死了这条路。**能一次证伪的假设，不要靠反复试参数去逼近。**

2. **一个量只能在一个空间里有意义。**
   排查中曾把 rest 局部量与世界量混在一起推导，得出过"pole / root / goal 三点共线"的错误结论，
   浪费了一轮。空间的记账必须严格：每个量进入推导前先确认它在哪个空间。

3. **尺度归一化是算法的一部分，不是优化项。**
   Blender 在 `Solve()` 开头把目标、关节位置、骨长偏移整体缩放到"链长 ≈ 1"的无量纲空间
   （`ComputeScale() = 1/ΣMaxExtension`），解完再缩放回去。于是 `1e-3` 阈值、`45°` 角度上限、
   阻尼系数之间是同一套相对关系。直接在世界单位里迭代时，"同一个算法"其实不是同一个算法——
   这是"Blender 收敛而我们发散"的结构性原因。

4. **收敛判据的选择会改变解本身。**
   Blender 只看角度增量范数（`IK_QJacobian::AngleUpdateNorm()`，即 `max(|dθ_i · norm_weight_i|)`），
   不看位置残差。位置判据对"目标够不到"的链永远不成立 → 每次都跑满迭代上限、停在半途 →
   输出重新变成起点的函数 → 抖动。
   因此"精度没到就继续迭代""精度到了就提前退出"这两类看似无害的优化，**都是抖动的来源**。

5. **角度增量必须"局部 basis 右乘 + 从根级联"。**
   用"全局左乘 + 手动传播下游"会不收敛/发散（仿真对比：左乘从 ~0.3 振荡发散到 8+；
   右乘局部 basis 收敛到 0.002 @ iter16）。Blender 的 `IK_QSphericalSegment::UpdateAngle`
   是 `m_new_basis = m_basis * M`，全局旋转通过 `root->UpdateTransform` 从根级联重算。

## 三、移植参照实现的方法论

这是本次最有复用价值的部分。

### 3.1 区分"算法结构"与"数据前提"

Blender 的 `IK_QJacobianSolver::ConstrainPoleVector` 在**迭代前**预旋转整条链，其数学成立的前提是
**起点末端不在目标上**（因此 `dir != poledir`，约束矩阵非平凡）。

- 结构可以照抄；
- 前提不能假设。

我们的数据源不满足该前提（起点末端恰好压在目标上），硬搬公式得到的是恒等矩阵——
如果不去核对前提，就会花几天去调试一个**在数学上不可能生效**的项。

### 3.2 前提不成立时，搬语义而不是搬公式

Blender 的 pole 语义是"链的弯曲平面朝向由 pole target 决定"。
我们在解算结束后，把整条链**绕「链根 → 末端」轴刚性旋转**一个角度，使链的弯曲平面与
「链根 / 末端 / pole target」三点确定的平面重合：

- 根与末端都在旋转轴上 → **末端位置、骨长、相对构型全部不变**；
- 只有链的朝向改变 —— 这正是 pole 的语义；
- 退化情形（直链没有可定义的弯曲平面、pole 落在链轴上）显式跳过。

移动 pole target 一定能改变链的朝向，效果与 Blender 的 pole 一致。

### 3.3 允许的偏离必须写清理由

当前相对 Blender 的**有意偏离**只有两条，且都能一句话说明原因：

| 偏离 | 原因 |
|---|---|
| 收敛判据多一条"停滞检测" | 目标够不到（链已伸直）时雅可比近奇异，角度增量会在小范围来回摆，Blender 的 1e-3 判据压不到，跑到迭代上限只会让输出停在"半途" |
| pole 走"解后平面对齐"而非 `ConstrainPoleVector` | 本节点输入姿态 == 输出姿态，`dir == poledir`，原约束结构性失效 |

### 3.4 诚实列出还差什么

要 100% 对齐 Blender，需要在 rig 中把 **IK 输出写到独立骨骼**（FH/IK 骨骼分离），
让求解起点真正来自"动画姿态"而非 IK 输出——那时 `ConstrainPoleVector` 才会非平凡。

这是**架构差异**，不是算法差异。知道边界在哪里，比假装已经一致有价值得多。

## 四、工程纪律（本次浪费时间最多的环节）

1. **先证明"我改的代码真的在跑"，再相信任何日志。**
   陈旧二进制骗了好几轮：编辑器没有重启、UBT 报 `Target is up to date`、
   旧的字面量还在日志里打印，于是同一个"修复"被反复验证。
   后来靠 **DLL 时间戳 + 字符串搜索**（`UnrealEditor-MusicDollCommon.dll`，UTF-8 存元数据、
   UTF-16 存部分字面量）才把这一环钉死。

   > 结论的可信度上限 = 运行体的新鲜度。

   本项目注意点：无 LiveCoding，改完 C++ 必须**完全关闭编辑器**再重新构建、启动。

2. **一次性自检日志值得写，但结论坐实当天就该删。**
   `[几何]` 自检回答了"骨长轴到底是不是局部 X、rootz 与骨长轴夹角多少"，
   `[FK]` 自检回答了"`InitialLocal` 到底干不干净"——这些直接终结了长期靠假设的东西，价值极高。
   但留在代码里就是噪音，也是下一次误判的源头。

3. **诊断量必须与求解量同空间。**
   求解在缩放空间进行、日志打世界空间，读日志的人必然算错一次。

4. **多线程下的 `static` 是雷。**
   Control Rig 可能在多个线程求值同一节点。函数内 `static TMap` 会被并发写坏内部
   `SparseArray`（表现为 `SparseArray.h` 的 `AllocationFlags` 断言崩溃）。
   要么 `thread_local`，要么干脆不要缓存。

5. **症状补丁会在根因修复后变成负债。**
   中途加的"目标静止就沿用上次解"确实压住了抖动（它治的是"起点不确定"的症状）。
   根因修好（起点确定）之后，这个缓存立刻变成纯负债并已被删除。
   能识别并回收症状补丁，和当初写出它同样重要。

6. **脚手架要在"完美"之后立刻拆。**
   确认效果达标的那一刻，就该删死分支、死属性、死缓存。
   留着的每一个失效旋钮，都会在半年后变成"这个参数到底有没有用"的考古题目。

## 五、最终状态速查

### 5.1 节点属性（`BlenderStyleIK.h`）

| 属性 | 说明 |
|---|---|
| `EndBone` / `ChainLength` | 从末端骨骼沿父级链向上取 `ChainLength` 根骨骼 |
| `EffectorTransform` | 世界空间目标变换 |
| `Weight` | 0~1 插值（`Weight=0` 时落回求解起点姿态） |
| `MaxIterations` | 默认 100；实际求解远早于此收敛（实测 `iter=12`），只是发散时的兜底 |
| `bPropagateToChildren` | true → 末端关节世界旋转取 Effector 的旋转；false → 保持级联朝向 |
| `PoleTarget` | 引导链弯曲平面朝向该目标 |
| `MaxAnglePerStep` | 单步最大角度变化（度），对应 Blender `max_angle_change = PI/4` |

### 5.2 求解主流程

1. 从末端骨骼向上构建链（根在前）→ 反转；
2. 用 `InitialLocal` 级联 + 根骨骼父级的实时姿态，重建"未被 IK 解算过的 FK 姿态"作为**起点**；
3. 缩放归一化（`1/链总长`）；
4. 迭代：位置任务残差 + 单步 clamp → 世界列雅可比 → SDLS 伪逆 → Basis 右乘 → 从根级联 → 位置级联；
5. 收敛：`Iter > 10 && AngleUpdateNorm < 1e-3`（Blender 口径），另有停滞检测兜底；
6. 还原尺度；
7. `AlignChainPlaneToPole` 做解后 pole 对齐；
8. `bPropagateToChildren` 决定末端旋转；
9. 写回层级（含 `Weight` 插值）。

### 5.3 一句话

> **末端到位不等于解稳定。**
> 稳定性来自"起点确定 + 判据与参照实现同口径"，
> 而不是来自更多的迭代、更小的阻尼或更聪明的提前退出。
> 遇到"大体对、局部乱跳"，先查输入语义，再查数学。
